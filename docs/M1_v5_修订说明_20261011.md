## 一、修订一：确认位切换死代码修复（quant/weekly_gate.py）

**原 bug**：confirm = 最低点后运行最高 high（含当日），切换条件 close > confirm —— close 恒 ≤ 当日
high，thrust 分支永不触发（现状恰为 pullback 才没出错）。

**新口径 = 确认位状态机**（方案本意"确认位=4浪底后反弹高，突破确认/跌破证伪"）：
- 确认位 = 最低低点之后、截至【前一日】的反弹高（不含当日）
- 收盘突破确认位 → 新推动确认（thrust），确认位**冻结**为失效线（不随新高上移，杜绝横跳）
- 确认后收盘跌回确认位之下 → 证伪退回保守 pullback 计数（反弹高重新累积）
- 未确认前一律 pullback（证伪优先）

**复查**：上证确认位由机械计算复现 **3995.18**（=5-1 浪顶，与方案写死值一致但零硬编码）。
注：此前"首个 zigzag 摆点高"方案被否——post 段自跳空日开始时 4% 阈值下摆点为空，机械定义过脆。

## 二、修订二：硬闸门相位修正（quant/env_gate.py）

- 硬闸门只对 **pullback r≥1（破起点）** 生效，输出"数浪失效·须重数"标记
- thrust 的 extension（1.0~1.3 为"推进中全仓"）不再触发硬闸门（原代码会把 wave5 推进 100% 打成 0）
- **决策三段化**（中间档无历史边际，废除 4 档标签决策语义）：
  `env≥0.8 → full 全信` / `0.35~0.8 → observe 观察不表态` / `<0.35 → reject 拒绝开新仓`
  系数仍连续输出；对接 M2/M3 只用三段决策。当前 0.717 → **observe**（诚实口径）

## 六、机械数浪评估：能否无写死数值？

**测试**（scripts/m1_wave_auto_check.py，reports/m2/m1_wave_auto_check.json）：
wave_counter 纯机械（HL-zigzag + 选点式 impulse + I2/I3/I4 硬规则，零人工输入）vs 人工金标准，
2024-10 起月度采样 × 三阈值（6%/8%/10%），容差 日期±15交易日/价格±3%。

| 边界 | 机械首次识别滞后 | 评价 |
|---|---|---|
| 1浪顶(2024-10)/2浪底(2025-04) 大级别转折 | **120~312 交易日**（约 0.5~1.5 年） | ❌ 不可用 |
| 3浪顶(2026-05~07) 中级别 | 3~20 交易日 | ✅ 可用 |
| 4浪低点(2026-07) | 13~30 交易日 | ✅ 可用 |

**结论（如实）**：
1. **大框架仍需人工锁定**——纯机械对大级别转折的识别滞后半年以上（2浪底这类十年大底，
   机械 zigzag 在确认时早已涨走 20%+），与定稿方案"人工锁定大框架、机械只算子浪"的设计判断一致，
   本次用数据实证了它。
2. **框架内已 100% 机械化、零写死**：fib 档、确认位（3995.18 机械复现）、最低低点、日线摆点、
   破起点判定、regime 推导全部由数据算出；唯一人工输入 = wave_labels 浪型锁定 + 指数清单。
3. 机械数浪器对**框架内子浪**（3浪顶/4浪底级别）可靠（滞后 3~30 日），可作为人工锁定的
   辅助校验与"破位重数"的触发器（跌破失效位自动提示重数）。
4. 剩余参数（zigzag thr=4%/10%、heuristic 过滤 r3∈[0.8,4.5] 等）是波浪理论经验值/缩放容差，
   已进 algo_version 版本管理；fib 38.2/50/61.8、1.3/1.5/1.6 为波浪/斐波那契理论常数。
