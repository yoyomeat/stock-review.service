## 一、本次工作内容

### 1. T+1违规修复

**问题**：回测引擎中T+1保护逻辑用 `>` 而非 `>=`，导致执行日当天（D+1）也可卖出，违反A股T+1制度。

**修复**：

| 文件 | 修改 | 说明 |
|------|------|------|
| quant/bt_order_executor.py | `entry_idx_map[code] = day_idx + 1` | 所有买入统一为day_idx+1 |
| quant/bt_position_manager.py | 5处 `> day_idx` → `>= day_idx` | T+1保护条件 |
| backtest_engine.py | 4处 `== i` → `== i + 1` | Mark-to-market买入当天 |

**验证**：173 tests pass

### 2. 主线降级过滤器优化

**问题**：原过滤器只在冰点期检查降级，其他时期不检查。

**修复**：将条件从"冰点期+降级"改为"任何时期降级就不买"

```python
# 旧代码
lambda ctx: '冰点' in ctx.cycle_phase and getattr(ctx, 'tracker_degraded_days', 0) > 0

# 新代码
lambda ctx: getattr(ctx, 'tracker_degraded_days', 0) > 0
```

### 3. 新增数据驱动过滤器

**基于大额亏损分析**，新增2个过滤器：

| 过滤器 | 条件 | 说明 |
|--------|------|------|
| 强势市场高振幅过滤 | amplitude > 15% AND sentiment >= 70 AND profit >= 60 | 只在强势市场过滤高振幅股票 |
| 高换手率过滤 | turnover_rate > 50 | 高换手率说明筹码交换激烈 |

**分析发现**：
- 强势市场：高振幅股票表现差（WR=33%），应该过滤
- 正常市场：高振幅股票表现好（WR=62%），应该保留
- 弱势市场：高振幅股票略好，可以保留

**修改文件**：
- `config/context.py`: +2字段 (amplitude, turnover_rate)
- `quant/trade_plan.py`: 计算振幅和换手率，传递给MarketContext
- `quant/filters.py`: +2个过滤器（条件性高振幅过滤）

### 4. 持有期配置优化

**问题**：所有策略持有期都是2天，太短。

**修复**：

MAINLINE_HOLD_DAYS = {

### 5. KPH50 fallback机制

**问题**：KPH50数据某些日期缺少板块，导致mainline_pool为空。

**修复**：在 `_load_plate_stocks_from_kph()` 中添加fallback逻辑，当KPH50数据缺少板块时，从KPH full数据加载。

**修改文件**：`quant/mainline_tracker.py`
- 添加 `import json`
- 新增 `_load_plate_stocks_from_kph_full()` 函数
- 修改 `_load_plate_stocks_from_kph()` 添加fallback

### 6. trade_plan.py 升级路径修复

**问题**：升级路径（EARLY→CONFIRMED）生成picks后，mainline_status未更新。

**修复**：在升级路径生成picks后，更新mainline_status为"confirmed"。

### 7. trade_plan.py 大小写修复

**问题**：mainline_tracker状态为大写"CONFIRMED"，但trade_plan.py检查的是小写"confirmed"。

**修复**：添加 `.upper()` 到状态检查。

### 8. 流通市值修复

**问题**：CSV数据中流通市值为0，导致换手率计算错误。

**修复**：创建 `scripts/fix_turnover_rate.py` 和 `scripts/fetch_all_csv_levistock.py`，用levistock数据修复流通市值和换手率。
