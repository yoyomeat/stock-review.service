## 二、问题分析

### 2.1 Fix J 重复过滤（picks 被误杀）

**现象**：01/13 review 的 trade_plan.picks 为空，但 summary 显示"主线策略，首选华塑科技"。

**根因**：`quant/trade_plan.py` 第863行的 Fix J 逻辑用**当天 tracker** 过滤**前一天的选股**，逻辑矛盾。

**完整链路**（以01/13为例）：
1. `prev_meta` = 01/10 tracker → 算力 = CONFIRMED，mainline_pool 有 301157 华塑科技
2. `_select_mainline_stocks` 选出 301157，source = "CONFIRMED·算力"
3. Fix J 读当天（01/13）tracker → 算力 = DEGRADED
4. 301157 的 source `endswith("·算力")` → 被过滤
5. picks 变空，summary 未更新 → 残留"首选华塑科技"

**结论**：`_select_mainline_stocks` 已根据 prev_meta 处理 DEGRADED（返回空），Fix J 是冗余且有害的二次过滤。

### 2.2 多主线 CANDIDATE 被跳过

**现象**：当有 CONFIRMED 板块时，CANDIDATE 板块完全不选股。

**根因**：`_select_mainline_stocks` 按优先级排序后 break，只处理最高优先级状态的板块。

**代码位置**：
```python
for _ap, _as in _active_mains:
    _st = _as.get('status', '')
    if _st != _top_status:
        break  # 只处理同优先级的板块 ← 问题所在
```

**结论**：CONC 确认的板块都应有机会选股，CANDIDATE 试探仓和 CONFIRMED 主力仓应共存（MAINLINE_FRAMEWORK.md §三明确写了共存机制）。

### 2.3 多板块仓位溢出

**现象**：多板块选股后仓位叠加超过100%。

**数据**：
| 日期 | picks | 总仓位 |
|------|-------|--------|
| 01/09 | 华塑科技84% + 海得控制84% | 168% |
| 01/16 | 震裕科技63% + 苏豪弘业63% | 126% |

**原因**：每个板块独立计算 MAINLINE_BASE_POS(70) x POS_MULT，无总仓位约束。

## 三、修复方案

### 修改原则
- 单一修改点：只改 `quant/trade_plan.py` 1个文件
- 禁止反向依赖：不改 config/、pipeline.py、review_new.py
- 策略函数只做计算

### Fix 1：删除 Fix J（~15行删除）

**文件**：`quant/trade_plan.py` 第863-876行

**删除内容**：
```python
# Fix J: filter out picks from DEGRADED plates (current tracker vs prev_meta)
_cur_tracker = sec.get("mainline_tracker", {}) if sec else {}
if _cur_tracker:
    _degraded_plates = {p for p, s in _cur_tracker.items()
                        if isinstance(s, dict) and s.get("status") == "DEGRADED"}
    if _degraded_plates:
        ...
```

**理由**：选股过滤应统一在 `_select_mainline_stocks` 一处完成，不应在调用方二次过滤。

### Fix 2：多主线全板块选股（删除 break）

**文件**：`quant/trade_plan.py` 第244-245行

**删除内容**：
```python
if _st != _top_status:
    break  # 只处理同优先级的板块
```

**理由**：所有 CONFIRMED/CANDIDATE 板块都应参与选股，每个板块按自身状态取 top1。

### Fix 3：总仓位归一化（新增4行）

**文件**：`quant/trade_plan.py` 第706行（picks 构造循环后、summary 赋值前）

**新增内容**：
```python
# 总仓位归一化：超过100%时按比例缩放
_sum_alloc = sum(p.get("allocation", 0) for p in plan["picks"])
if _sum_alloc > 100:
    _scale = 100.0 / _sum_alloc
    for _p in plan["picks"]:
        _p["allocation"] = max(1, round(_p["allocation"] * _scale))
```

**理由**：多板块选股后仓位叠加可能超过100%，需按比例缩放至上限。
