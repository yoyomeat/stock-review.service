## 一、反弹确认期：触发条件确认

### 问题

原框架提出反弹确认期作为冰点→上升的过渡态，但未明确触发条件。

### 数据分析

**下降期prof>50 + CONC_EARLY的情况：**
- 下降期总转换168次，其中prof>50占90次（54%）
- prof>50 + CONC_EARLY占56次（33%）
- 连续2+天prof>50 + CONC_EARLY的8个序列，**成功率0%**

**结论：下降期的CONC_EARLY只是抱团指引，不是上升标志。**

### 确认方案

**反弹确认期只从冰点期触发，不从下降期触发：**

```
冰点期 → sent/prof 恢复（core_sent≥30 且 prof>50 且恢复≥15）
  ├── 有 CONC_EARLY/CONFIRM/STRONG → 上升期（直接确认）
  ├── 无 CONC → 反弹确认期（等待观察）
  └── 未恢复 → 冰点期延续 或 下降期
```

## 二、冰点→上升：无CONC信号的处理

### 数据分析

21次冰点→上升中：
- 上升日有CONC信号：11次
- 上升日无CONC信号：10次

关键发现：**CONC信号出现在上升日，不是冰点日。**

| 冰点日 | 上升日 | 冰点日conc | 上升日conc |
|--------|--------|-----------|-----------|
| 20250113 | 20250114 | CONC_WATCH | CONC_STRONG |
| 20250331 | 20250401 | 无 | CONC_EARLY |
| 20250827 | 20250828 | 无 | 无 |

### 无CONC的3个案例后续表现

| 案例 | D+1 | D+2 | 结果 |
|------|-----|-----|------|
| 20250828 | 上升D1(prof=58) | **下降D1(prof=31)** | 假信号 |
| 20260203 | 上升D1(prof=61) | 上升D2(CONC_EARLY) → 冰点 | 不稳定 |
| 20260407 | 上升D1(prof=70) | 上升D2(CONC_EARLY) → 持续上升 | 成功 |

### 确认方案

**所有冰点→恢复统一进入反弹确认期：**

```
冰点期 → sent/prof 恢复 → 反弹确认期
  ├── D+2 prof≥60 → 升级上升期（88.9%精确率）
  ├── D+2 prof≥55 + 有CONC → 升级上升期（87.5%精确率）
  ├── D+2 prof<50 → 退回下降期
  └── 50≤prof<55 → 继续观察（最多5天）
```

**效果：**
- 成功组13个：8-10个能升级（62%-77%）
- 失败组8个：6-7个能过滤掉（75%-88%）

## 三、有CONC直接进上升的风险

### 数据分析

17个有CONC的冰点→上升案例：
- 成功持续上升：9个（53%）
- 假上升（3天内回到冰点/下降）：8个（**47%**）

| 假上升案例 | 上升日信号 | 崩溃速度 |
|-----------|-----------|---------|
| 20260528 | CONC_EARLY | 1天（prof 68→8） |
| 20251015 | CONC_EARLY | 2天 |
| 20260518 | CONC_STRONG | 3天 |

**结论：即使有CONC信号，近一半是假信号。必须统一进反弹确认期。**

## 五、下降期定义与分析

### 核心任务

1. 如何准确判断还在下降期？（包括途中的反弹）
2. 如何准确发现上升期开始了？

### 数据发现

**下降期特征：**
- 50个下降期段落，大多数1-4天
- 途中prof>50反弹出现18次，但50%会再次下跌

**下降期反弹 vs 真正上升：**

| 指标 | 下降期反弹 | 真正上升开始 |
|------|:---------:|:----------:|
| prof均值 | 53.8 | 77.0 |
| sent均值 | 57.3 | 88.0 |

**关键区别：prof和sent的水平！**

### 上升期开始点分析

23个上升期开始点：
- 成功持续5天：10个（45%）
- 5天内退出：12个（55%）

| 指标 | 成功组 | 失败组 |
|------|:------:|:------:|
| prof均值 | 67.4 | 59.8 |
| sent均值 | 76.1 | 70.8 |
| prof跳升 | 38.0 | 35.4 |
| 有CONC% | 80% | 83% |

**结论：单靠prof/sent阈值难以精确区分，需要多维度验证。**

## 六、确认的框架

### 6.1 冰点期→上升期（通过反弹确认期）

```
冰点期 → sent/prof 恢复（core_sent≥30 且 prof>50 且恢复≥15）
  └── 进入反弹确认期

反弹确认期 → D+2 观察：
  ├── prof≥60 → 升级上升期（88.9%精确率）
  ├── prof≥55 + 有CONC → 升级上升期（87.5%精确率）
  ├── prof<50 → 退回下降期
  └── 50≤prof<55 → 继续观察（最多5天）
```

### 6.2 下降期判断

```
下降期进入：
  prof<55 且 sent<65（连续2天确认）

下降期退出（可能进入上升）：
  prof≥60 且 sent≥70（单日触发，进入观察）

下降期确认退出（真正上升）：
  连续2天 prof≥55 且 sent<65（确认上升期）
```

### 6.3 下降期子阶段

**结论：不做子阶段划分，只标记天数。**

原因：
- 子阶段难以量化
- prof>50在下降期太常见（43.9%），不能作为子阶段标志
- CONC信号在下降期只是抱团指引，不是上升标志

### 6.4 CONC信号的定位

- **冰点期CONC**：新主线启动信号，可直接进上升期
- **下降期CONC**：抱团指引，不作为上升标志
- **反弹确认期CONC**：确认信号，用于升级到上升期
