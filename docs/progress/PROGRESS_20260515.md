## 一、Leader Break 退出机制 Bug 修复

### 1.1 Bug 根因

`check_leader_break()` 的 CONFIRMED 分支存在三层 bug：

| # | Bug | 影响 |
|---|-----|------|
| 1 | `prev_leader` 从 `prev_meta['_kph_data']` 读取 | 永远 None（meta 中无此字段） |
| 2 | fallback 到 `prev_lb['new_leader']`/`prev_lb['prev_leader']` | 首次进入时均为 None |
| 3 | AIR_REFUEL→CONFIRMED 返回 `prev_leader=None` | 恢复后丢失龙头信息 |
| 4 | 首次进入 CONFIRMED（prev_conc 非 confirmed）时不存 leader | 次日无法做断板检测 |
| 5 | `prev_leader` 无 fallback 到 `concentration.leader` | 跨日龙头信息断裂 |

**连锁反应**：用今日龙头检查"是否断板" → 永远检测不到断板。

### 1.2 修复方案

**文件**: `quant/anchor_monitor.py` 的 `check_leader_break` 函数

| # | 改动 |
|---|------|
| 1 | `prev_leader` 改为 `prev_lb.get('prev_leader')` |
| 2 | 新增 fallback：`prev_meta['concentration']['leader']`（同板块时） |
| 3 | AIR_REFUEL→CONFIRMED 存 `new_leaders[0]` 为 prev_leader |
| 4 | 所有 CONFIRMED 返回存 `prev_leader=today_leader` |
| 5 | 早期返回分支也存 leader 信息（plate + prev_leader） |

### 1.3 验证

- pytest: 48/48 通过
- 0109→0110→0113 端到端验证：
  - 0109: CONC_WATCH(算力), leader=川润股份(15ban) → 存入 concentration
  - 0110: CONC_CONTRARIAN(机器人), leader=弘讯科技(6ban) → 存入 leader_break
  - 0113: prev_leader=弘讯科技 → 弘讯科技断板 → 瑞松科技接棒 → CONFIRMED ✅

## 二、CONC_EARLY 信号实现

### 2.1 设计依据

来源: `PROGRESS_20260514_signal_mechanism.md` §3.1

```
两层入场机制（EARLY + CONFIRMED）:
  EARLY:     跳入TOP1 + 连板>=3  → 早期信号（寻找题材启动期）
  CONFIRMED: TOP1     + 连板>=4  → 确认信号
```

用户明确：EARLY/WATCH/CONFIRM 是**仓位递增**关系：
- EARLY → 试错仓
- WATCH → 加仓
- CONFIRM → 重仓
- EXIT → 清仓

### 2.2 信号条件

| 信号 | 条件 | 信号级别 | 仓位 |
|------|------|---------|------|
| CONC_CONTRARIAN | 集中度≥50% + 板块跌 + sent<50 | confirm | 重仓 |
| CONC_STRONG | 集中度≥60% + TOP1 | confirm | 重仓 |
| CONC_CONFIRM | 集中度≥50% + TOP1 + 连板≥4 | confirm | 重仓 |
| **CONC_EARLY** 🆕 | TOP1 + 最高连板数≥3（无集中度门槛） | early | 试错 |
| CONC_WATCH | TOP3 + 集中度≥40% + 连板≥1 | watch | 加仓 |

**关键设计决策**：
- CONC_EARLY 不要求集中度（题材启动初期集中度尚未形成）
- CONC_EARLY 只要 TOP1（连板≥3 本身就是强信号）
- CONC_EARLY 用**最高连板数**（从 limit_tag 解析），不用连板股数量

### 2.3 连板数解析

发现 `limit_count` 字段**不是**连板数：
- "8天7板" → limit_count=6（不是7）
- "5连板" → limit_count=2（不是5）

新增 `_parse_max_lianban()` 函数，从 `limit_tag` 字符串解析：
- `X连板` → X
- `X天Y板` → Y
- `首板` → 1

### 2.4 修改文件

| # | 文件 | 改动 |
|---|------|------|
| 1 | `config/strategy_rules.py` | 无改动（阈值暂放 anchor_monitor.py，后续可迁移） |
| 2 | `quant/anchor_monitor.py` | 新增 `CONC_EARLY_LIANBAN=3`、`_parse_max_lianban()`、CONC_EARLY 检测逻辑、build_mainline_info 处理 |
| 3 | `quant/review_new.py` | signal_level 映射：CONC_EARLY→early, CONC_WATCH→watch, confirmed→confirm；tracker_state 映射 early→ACTIVE |
| 4 | `quant/selector.py` | EARLY 路径条件改为 `signal_level == 'early'`（只有 CONC_EARLY 走快速路径） |

### 2.5 信号流转

```
anchor_monitor.py          review_new.py         selector.py           theme_ranker.py
─────────────────         ───────────────        ─────────────         ─────────────────
CONC_EARLY  ──────→  signal_level='early' ─→ EARLY快速路径  ───→  early权重(抗分歧0.35)
CONC_WATCH  ──────→  signal_level='watch' ─→ 主线路径      ───→  confirm权重(身位0.35)
CONC_CONFIRM ─────→  signal_level='confirm'→ 主线路径      ───→  confirm权重(身位0.35)
```
