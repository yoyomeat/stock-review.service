### 二、排除的问题（非 bug）

#### 2.1 positions[i]=0 但有 new_trades（118天）

**结论：T+1 显示效果，非 bug。**

API 的 positions 数组 = day_end_exposure，计算时排除 _open_day_idx == i 的当天新开仓。D 日开仓 -> D 日 positions=0 -> D+1 才计入。118 天中 71 天 D+1 确实生效。

#### 2.2 NAV 计算公式

**结论：正确，无双重计算。**

公式 daily_change = daily_pnl + (unrealized_pnl - prev_total) 经逐笔验证：
- daily_pnl = 已实现盈亏（含费用）
- unrealized_change = 浮盈变化
- 两者不重叠，手动计算与 NAV 误差 <0.2 元

- 实际回测: 57笔中21笔被止损（37%），止损吃掉 2-3% 收益

### 冰点期止损有害的原因
1. 市场最恐慌，日内波动 -5%~-15% 很常见（61%股票有回撤）
2. 60-69% 触达止损后会反弹 — 典型假摔
3. 真正风控靠：仓位管理（冰点期仓位低15-30%）+ regime退出（退潮/断崖 exit_all）

### 修改
`config/strategy_rules.py` STRATEGY_EXIT_RULES 3行：
- `"ice_point":     ("stop_entry_pct", -5, ...) → ("stop_none", None, ...)`
- `"ice_point_t1":  ("stop_entry_pct", -5, ...) → ("stop_none", None, ...)`
- `"ice_point_t2":  ("stop_entry_pct", -5, ...) → ("stop_none", None, ...)`

hold_days 不变（2/2/3），EntryGen 中的 stop_loss 被 ExitEngine 的 stop_none 覆盖。
