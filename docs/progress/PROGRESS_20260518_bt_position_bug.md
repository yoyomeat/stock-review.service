## 一、问题发现

在逐月分析亏损原因时，发现 2025 年 2 月的回测收益与新炬网络(605398)的实际涨幅严重不符。

新炬网络 02/05~02/12 连续涨停 8 天（27.9→49.45，累计 +77%），但回测净值仅从 12073 涨到 13391（+10.9%），远低于预期。

## 二、回测引擎买入机制确认

### 2.1 代码位置

`backtest_engine.py` L685-692：

```python
np = next_prices.get(code)      # next_prices = load_day_prices(next_date)
```

```python
if p.get("_open_day_idx") == i:
    curr_unrealized_map[code] = 0.0   # 买入当天不计浮盈

```

### 2.3 NAV 计算

## 三、核心矛盾：positions 数组与 equity curve 不一致

### 3.1 positions 的含义

`backtest_engine.py` L778-783：

```python
day_end_exposure = round(sum(
    p["alloc"] for p in open_positions.values()
    if p.get("_open_day_idx") != i    # 排除当日买入（T+1）
), 1)
positions_list.append(day_end_exposure)
```

positions[i] = 当日收盘时的实际持仓暴露率（排除 T+1 仓位）。

### 3.2 矛盾现象

以 02/05 为例：

| 项目 | 值 |
|------|------|
| 02/05 review picks | 新炬网络 30% |
| positions[18] (02/05) | 30% |
| equity[18] (02/05) | 12073.01 |
| equity[17] (01/27) | 11433.50 |
| 日收益 | +5.59% |

如果 02/05 review 的 picks 在 D+1（02/06）才执行：
- 02/05 当天不应该有新仓位
- positions[18] 应该 = 0（或继承 01/27 的残余仓位）
- 但实际 positions[18] = 30%，与 review picks 完全一致

如果 02/05 review 的 picks 在 D+0（02/05 当天）执行：
- positions[18] = 30% ✓ 符合
- 但 T+1 保护 → 当天 unrealized = 0
- 02/05 的 +5.59% 收益应该来自 realized P&L（卖出旧仓位）
- 而非新炬网络的浮盈

### 3.3 数学验证

假设系统在 D日 以 pos% 仓位持有新炬网络，新炬涨停 +10%，则对 NAV 的贡献 = pos% × 10%。

**假设 A：pos[i] 是当天贡献收益的仓位（无 T+1）**

| 日期 | pos[i] | 新炬涨幅 | 预期贡献 | 实际收益 | "其他" |
|------|--------|----------|----------|----------|--------|
| 02/05 | 30% | +10% | +3.0% | +5.59% | +2.59% |
| 02/06 | 39% | +10% | +3.9% | +1.83% | -2.07% |
| 02/07 | 50% | +10% | +5.0% | -0.44% | **-5.45%** |
| 02/10 | 39% | +10% | +3.9% | +5.52% | +1.62% |
| 02/11 | 0% | +10% | 0% | +3.68% | **+3.68%** |
| 02/12 | 37% | +10% | +3.7% | -3.40% | **-7.10%** |

02/07 的 -5.45%、02/12 的 -7.10% 极不合理（其他持仓单日亏 5-7%？）。

**假设 B：pos[i-1] 是当天贡献收益的仓位（有 T+1）**

| 日期 | pos[i-1] | 新炬涨幅 | 预期贡献 | 实际收益 | "其他" |
|------|----------|----------|----------|----------|--------|
| 02/05 | 48% | +10% | +4.8% | +5.59% | +0.79% |
| 02/06 | 30% | +10% | +3.0% | +1.83% | -1.17% |
| 02/07 | 39% | +10% | +3.9% | -0.44% | **-4.35%** |
| 02/10 | 50% | +10% | +5.0% | +5.52% | +0.52% |
| 02/11 | 39% | +10% | +3.9% | +3.68% | -0.22% |
| 02/12 | 0% | +10% | 0% | -3.40% | **-3.40%** |

02/05 的 48% 来自 01/27 的仓位（冰点期清仓后不应存在）。
02/07 的 -4.35%、02/12 的 -3.40% 仍然偏高。

**两个假设都无法干净解释收益，说明 positions 数组和 equity curve 之间存在系统性偏差。**

## 四、根因推测（待验证）

### 假设 1：positions 记录时机问题

`day_end_exposure` 在 mark-to-market **之后**计算（L778 在 L747 之后）。
如果开仓在 mark-to-market 之前执行，positions[i] 包含了当天新开的仓位，
但 T+1 保护让该仓位对当天 NAV 贡献 = 0。

→ positions[i] 显示的是「当天结束时的仓位」，
但 NAV 反映的是「当天开始时的仓位 + realized P&L」。
两者口径不同。

### 假设 2：旧仓位未正确清理

从 01/27 到 02/05 有春节假期（无交易日）。
01/27 review 的 picks（普联软件 50%）在 02/05 执行？
还是被 02/05 review 的 picks 替代？

如果旧 picks 在假期后仍被执行，会导致 02/05 同时持有新炬 + 普联软件，
仓位超过 100%，但 positions 显示 30%，矛盾。

### 假设 3：regime 切换清仓时机

`backtest_engine.py` L509-530：

```python
if _prev_cycle.startswith(_healthy) and _curr_cycle.startswith(_danger):
    # 强制清仓旧持仓
```

01/24（上升D1）→ 01/27（冰点期）触发清仓。
但清仓发生在 01/27 的 mark-to-market 阶段。
如果 01/27 的 review picks（普联软件 50%）也在同一天执行，
会产生「先清仓、再开仓」的时序问题。
