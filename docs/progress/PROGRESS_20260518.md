## 二、29 个失败日期修复

### 2.1 根因分析

全部 29 个失败都是同一个 bug，在 `quant/style.py:351`：

```python
# 函数签名声明 has_mainline_init 是 bool
def calc_style(..., has_mainline_init: bool = False, ...):

# 但第 351 行用字符串 in 操作检查它
if "\u2705" in has_mainline_init:  # ← TypeError: argument of type 'bool' is not iterable
```

`has_mainline_init` 被声明为 `bool`（调用方传 `False`），但代码用 `"\u2705" in has_mainline_init` 做字符串包含检查，`in` 操作符不能用于 `bool` 类型。

只有 `_total >= 70 and _chain_score >= 15`（全面主升分支）时才走到这行代码，所以只有满足该条件的 29 天失败。

### 2.2 修复方案

按架构文档原则（单一修改点、最多影响两个文件、改完验证）：

- **文件**：`quant/style.py` 第 351 行

### 4.6 踩坑记录

Python 脚本写 Dart 代码时，`$` 符号处理需注意：
- Python 三引号字符串中 `\$` 会被写成字面量 `\$`（不是 Dart 的字符串插值）
- Dart 中 `$mo01` 会被解析为变量 `mo01`，需要写 `${mo}01`
- 正确做法：Python 中直接写 `$mo`（Python 不解释 `$`），对于 Dart 中 `$` 后紧跟数字的情况用 `${mo}01`
