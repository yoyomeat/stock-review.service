## 一、仓位 Bug 修复（已完成）

### 1.1 问题发现

通过分析 2025年1月数据，发现仓位普遍被限制在 15%，严重制约收益。

**核心问题**：`quant/position.py` 的 EARLY 仓位逻辑是"上限 cap"，而非"下限 floor"。

```python
# 旧逻辑（错误）
if _sig_level == 'early':
    if fp > _early_cap:          # 原始仓位 > 15%
        fp = _early_cap           # ❌ 强制压到 15%
```

**连锁反应**：
- 20250114 上升期 sent=97 prof=89：原始仓位 80% → 被压到 15%
- 20250107 反弹确认 sent=70 prof=70：原始仓位 58% → 被压到 15%
- 18 个交易日中 17 天仓位被压低

### 1.2 Bug 根因

`quant/position.py` 第 1085-1095 行：

```python
_sig_level = sec.get('_prev_signal_level', '')  # 优先读前日信号
if not _sig_level:
    _sig_level = _conc_data.get('signal_level', '')  # 兜底读当日信号
if _sig_level == 'early':
    fp = min(fp, 15)  # ❌ 只要前日是 EARLY，就 cap
```

**问题**：前日 EARLY + 当日升级为 CONFIRM → 仍然被 cap。升级信号被忽略。

### 1.3 修复方案

**核心原则**：信号仓位是下限保障，不是上限封顶。

```
原始仓位 > 信号仓位 → 维持原始仓位（市场强，不该压）
原始仓位 < 信号仓位 → 提到信号仓位（信号强，要给够）
```

**修改文件**：

| # | 文件 | 改动 | 备份 |
|---|------|------|------|
| 1 | `quant/position.py` | EARLY cap → 信号 floor | `.bak_20260515_pos_floor` |
| 2 | `quant/review_new.py` | 同步修改 | `.bak_20260515_pos_floor` |

**新逻辑**：

```python
# position.py
if _sig_level in ('early', 'watch', 'confirm'):
    _sig_floor = SIGNAL_POSITION.get(_sig_level, 0)
    if _sig_floor > fp:
        corr_notes.append(f'信号仓位下限{_sig_floor}%(原{fp}%)')
        fp = _sig_floor
    elif fp > _sig_floor:
        corr_notes.append(f'原始仓位{fp}%>信号下限{_sig_floor}%,维持原始')

# review_new.py
if _signal_level in ('early', 'watch', 'confirm'):
    _sig_floor = SIGNAL_POSITION.get(_signal_level, 0)
    _orig_pos = op.get('final_pos', 0)
    if _sig_floor > _orig_pos:
        op['final_pos'] = _sig_floor
    elif _orig_pos > _sig_floor:
        # 维持原始
```
