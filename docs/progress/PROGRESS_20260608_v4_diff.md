### 3.2 当前系统三个断裂点

#### 断裂点1：交易笔数少（86 vs 133）
- 当前系统通过 `backtest_engine.py` → `trade_plan.py` 重新生成 picks
- V4 直接读 review JSON 中已有的 `trade_plan.picks`
- 可能原因：`trade_plan.py` 在回测模式下 screener 路由未正确触发，或部分日期被跳过

#### 断裂点2：仓位过低（空仓率 64.6%）
- 当前系统空仓 193/345 天
- V4 在有 tracker CONFIRMED 信号时直接按仓位模型入场
- 可能原因：`trade_plan.py` 的仓位计算逻辑过严，或 cycle 状态机判定不开仓

#### 断裂点3：无止损兜底
- V4 有 SL-5% 止损，20笔触发，截断大亏损
- 当前系统 STRATEGY_EXIT_RULES 全面 stop_none
- 当前系统单笔最大亏 -14.11%（04/09），V4 最大单笔 -5%

### 3.3 数据流对比

```
V4 纯主线：
  review JSON → 直接读 picks + tracker → 模拟交易 → +530%

当前系统：
  review JSON → backtest_engine → trade_plan.py(重新生成picks) → 模拟交易 → +18.55%
```

**核心问题**：`trade_plan.py` 在回测模式下是否正确消费了 review JSON 中的 tracker 和 signal 数据？
