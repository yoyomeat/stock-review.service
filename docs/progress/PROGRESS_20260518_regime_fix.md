状态: 完成

## 一、问题发现

在分析 2025 年 2 月回测持仓时发现：新炬网络(605398) 01/24 开仓后，01/27 regime 切换清仓（上升期→冰点期）应将其完全清除，但该持仓以"幽灵"形式一直存活到 02/07，期间持续累积虚高浮盈。

## 二、根因分析

### 2.1 Bug 位置

`backtest_engine.py` 第 508-530 行，regime 切换清仓逻辑。

### 2.2 Bug 机制

regime 切换清仓分两步：
1. **close 循环**（L508-525）：遍历 open_positions，计算 P&L 加入 daily_pnl。但**没有 `del open_positions[code]`**
2. **过滤器**（L527-528）：`entry_idx_map.get(k, -1) == i` 本意是保留 T+1 保护的持仓

**问题**：
- `entry_idx == i` 表示"昨天开仓、今天可交易"的持仓 → **恰恰是应该被清掉的**
- `entry_idx > i`（即 `== i+1`）表示"今天开仓、T+1 保护"的持仓 → **应该保留的**
- 过滤条件写反了

### 2.3 幽灵持仓的后果

1. **P&L 重复计算**：close 循环算了 realized P&L，幽灵持仓继续累积 unrealized P&L
2. **入场价错误**：次日 picks 选同一只股票时触发"加仓/减仓"逻辑，沿用旧入场价而非 D+1 开盘价
3. **positions 数组失真**：包含已清仓的幽灵持仓，与 equity curve 不一致

### 2.4 影响范围

全量扫描发现 **30 天** 受影响（约 9%），贯穿整个回测期间（2025-01 ~ 2026-05）。

## 三、修复方案

### 3.1 改动

**文件**: `backtest_engine.py`，2 处改动

**改动 1**：close 循环内加 `del`（L525 之后）
```python
# 原来：只有 closed_today.append，没有 del
# 修复后：
                        del open_positions[_code]
                        entry_idx_map.pop(_code, None)
```

**改动 2**：过滤条件 `== i` → `> i`（L528、L556）
```python
# 原来：
open_positions = {k: v for k, v in open_positions.items()
                  if entry_idx_map.get(k, -1) == i}
# 修复后：
open_positions = {k: v for k, v in open_positions.items()
                  if entry_idx_map.get(k, -1) > i}
```

### 3.2 逻辑说明

- close 循环：有价格数据的持仓 → 直接 `del`（正确清除）
- 过滤器 `> i`：兜底保留 T+1 保护的持仓（今天开仓、尚不可交易）
- 停牌股（无价格数据）：不进入 close 的 `if _tp:` 分支 → 不被 `del` → 被过滤器保留（正确行为：停牌股不能卖出）
