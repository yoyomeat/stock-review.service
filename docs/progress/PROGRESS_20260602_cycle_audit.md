### 2.1 发现的问题

| 问题 | 数据 |

| 上升期 D3+ 无退出条件 | `_handle_uptrend` 中 cd≥3 直接返回上升期 |

| 分歧日→上升期无恢复检查 | 47.1% 弱恢复被放回上升期 |
| 最大 cycle_day | 37 |

### 2.2 修复方案

修改 `quant/position.py` → `_handle_divergence()`

```python
# 原代码
return "上升期第%d天" % (cd+1), cd+1, 0.85, streak, ["分歧日结束，回到上升"]

# 修复后
if sent >= 40 and prof >= 50:
    return "上升期第%d天" % (cd+1), cd+1, 0.85, streak, ["恢复良好回上升"]
else:
    return "上升分歧日第%d天" % cd, cd, 1.0, 0, ["弱恢复延续分歧"]
```

### 2.3 阈值选择

| 阈值 | 拦截数 | 拦截中差占比 | 放行中差占比 |

| sent≥50 AND prof≥50 | 10 | 80% | 56% |
| **sent≥40 AND prof≥50** | **8** | **100%** | **45%** |
| prof≥50 | 8 | 100% | 45% |

选择 sent≥40 AND prof≥50：以 prof 为主，sent 放宽到 40（只排除情绪崩盘），零误杀。

## 三、下降期审查（⚠️ 待修复）

### 3.1 发现的问题

当前退出条件 `prof>=50 AND core_sent>=60` **从未触发**（0/338天）。

原因：core_sent = sent - f3_score，f3 通常 9-15，所以 cs 比 sent 低 10-15 点。cs>=60 要求 sent>=70-75，实际数据中下降期的 sent 很少这么高。

review JSON 中的 15 次下降期→反弹确认期转换是旧代码遗留，当前代码会把它们全部打回下降期。
