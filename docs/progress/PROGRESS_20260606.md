## 二、发现的问题

### P0：21 个 Pick 走了旧路径（strategy=None + 无 buy_price）

**根因**：EARLY→CONFIRM 升级路径绕过了 Pipeline。

**代码路径**：
```
select_stocks()  →  返回 [{'code', 'name', 'role', 'source', 'score'}]
  ↓
plan['picks'] = _upgrade_picks   ← 直接赋值，跳过 _add_pick / Pipeline
  ↓
❌ 无 strategy / buy_price / stop_loss / sl_type
```

正常路径：
```
_select_mainline_stocks()  →  [{'code', 'name', 'role'}]
  ↓
_add_pick()  →  _build_stock_plan()  →  Pipeline.process()
  ↓
✅ strategy / buy_price / stop_loss / sl_type 全部填充
```

**受影响的 21 个 Pick**（17 个交易日）：
- 18 个：`主线·XX·身位排序`（`_select_from_mainline` via `select_stocks`）
- 3 个：`冰点逆情绪·XX`（`select_stocks` 的冰点分支）
- 日期范围：20250121 ~ 20260526

**子问题**：`_build_stock_plan` 中 `not row` 时返回半成品 pick（无 strategy/buy_price），应返回 None。

### P1：total_position 全部为 0

- 137 个有 picks 的日期，`trade_plan.total_position` 全部为 0 或 100（与 picks 不匹配）
- 个股 `pick['allocation']` 有值（5%~50%），但顶层汇总缺失
- 根因：`plan['total_position']` 读 `op['final_pos']`，该值经常为 0

### P1：regime 字段全部为 None

- `trade_plan.regime`：338 天全部为 None
- `trade_plan.regime_label`：有值（主升行情 172 / 抱团 89 / 低迷 41 / 散乱 36）
- 根因：`plan['regime']` 读 `op['regime']`（= `baotuan_subtype`），经常为 None

## 三、修复方案（严格遵循架构原则）

### 原则回顾
- 单一修改点：每个修复最多影响 2 个文件
- 禁止反向依赖：config 不 import quant
- 策略函数只做计算：不做条件判断
- 改前检查：改什么 / 为什么 / 怎么验证

### Fix 1a：`_build_stock_plan` 缺数据时返回 None

**文件**：`quant/trade_plan.py`（-3 +1）

```python
# 改前
if not row:
    pick['buy_type'] = '市价'
    pick['expectation'] = '无当日数据，市价委托'
    return pick

# 改后
if not row:
    return None  # 缺数据不构造半成品，由 _add_pick 跳过
```

**为什么**：半成品 pick 无 strategy/buy_price/stop_loss，回测和实盘都无法执行。

### Fix 1b：EARLY 升级 picks 走 `_add_pick` + Pipeline

**文件**：`quant/trade_plan.py`（-2 +10）

```python
# 改前
if _upgrade_picks:
    plan['picks'] = _upgrade_picks
    plan['summary'] = f'⬆ EARLY→{signal_level.upper()}升级...'

# 改后
if _upgrade_picks:
    for _up in _upgrade_picks:
        used_codes.discard(_up.get('code', ''))
    plan['picks'] = []
    for _up in _upgrade_picks:
        _add_pick(
            code=_up.get('code', ''), name=_up.get('name', ''),
            role=_up.get('role', ''), alloc_pct=_up.get('allocation', 10),
            source=_up.get('source', ''), boards=_up.get('boards', 0),
            board_race=_up.get('board_race', False),
            tracker_mainline_status='CONFIRMED',
            mainline_candidates=_upgrade_picks,
        )
    if plan['picks']:
        plan['summary'] = f'⬆ EARLY→{signal_level.upper()}升级...'
```

**为什么**：
1. `select_stocks()` 返回的 pick dict 无 strategy/buy_price/sl_type，必须走 Pipeline 补全
2. `used_codes.discard()` 清除主线路由尝试过的代码，允许重新走 Pipeline
3. `tracker_mainline_status='CONFIRMED'` 让 Pipeline._route() 识别为主线策略，而非 convergence

### Fix 2：total_position 从 picks 汇总

**文件**：`quant/trade_plan.py`（+4）

```python
# 在 return plan 前插入
if plan['picks']:
    _sum_alloc = sum(p.get('allocation', 0) for p in plan['picks'])
    if _sum_alloc > 0:
        plan['total_position'] = _sum_alloc
```

**为什么**：`op['final_pos']` 是周期仓位理论值，实际 picks 仓位可能因过滤、主线系数等调整。以 picks 实际仓位为准。

### Fix 3：regime 字段回退到 regime_label

**文件**：`quant/trade_plan.py`（~1）

```python
# 改前
'regime': op.get('regime', ''),

# 改后
'regime': op.get('regime') or op.get('regime_note', ''),
```

**为什么**：`op['regime']` = `baotuan_subtype`，经常为 None。`regime_note` 始终有值（主升行情/抱团行情等）。
