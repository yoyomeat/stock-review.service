## 修复方案

### 修复1: Pipeline 路由 invest_style 传递

**根因**: `pipeline.py:_route()` 创建 `AnchorResult(invest_style='', ...)` 但没有从 `ctx` 读取 invest_style。`MarketContext` 和 `_build_context()` 都没有 invest_style 字段。

**数据流**:
```
review_new.py:
  resolve_style() → _anchor_style (锚定风格: 上升健康/赚钱抱团/冰点反转...)
  _STYLE_MAP → _old_style (旧风格: 主升/抱团/低迷/散乱)
  sec['anchor_result']['invest_style'] = _anchor_style  ← 锚定风格存在这里
  sty['invest_style'] = _old_style  ← 旧风格存在这里

trade_plan.py:
  _build_context(... composition=sec['anchor_result']['composition'],
                     anchor_signals=sec['anchor_result']['anchor_signals'] ...)
  ❌ 没有传递 invest_style

pipeline.py:
  AnchorResult(invest_style='', ...)  ← 空字符串
```

**修复方案**: 在 `_build_context()` 和 `MarketContext` 中增加 `invest_style` 字段，从 `sec['anchor_result']['invest_style']` 传入。

**修改文件**:
1. `config/context.py`: MarketContext 增加 `invest_style: str = ''`
2. `quant/trade_plan.py:_build_context()`: 增加 `invest_style=''` 参数，传给 MarketContext
3. `quant/trade_plan.py:_build_stock_plan()`: 从 `sec['anchor_result']['invest_style']` 取值传入
4. `quant/pipeline.py:_route()`: 从 `ctx.invest_style` 读取，传给 AnchorResult

### 修复2: 清理 ROUTE_TABLE

**根因**: 旧策略归档时 ROUTE_TABLE 没有同步更新。

**当前状态**: STRATEGY_REGISTRY 只有 `mainline_confirmed` 和 `mainline_candidate`。

**修复方案**: 精简 ROUTE_TABLE，只保留实际可用的路由。由于当前所有选股都走生命周期路径（问题1的原因），标准路由从未生效。修复问题1后，需要决定：

**选项A（推荐）**: 清理 ROUTE_TABLE，只保留生命周期路由。将标准路由的 screener 全部设为 None（不选股），因为对应 screener 已归档。

**选项B**: 重新实现归档的 screener。工作量大，不推荐。

**修改文件**:
1. `quant/action_router.py`: 清理 ROUTE_TABLE，移除引用已归档 screener 的路由

### 修复3: 统一 mainline_info 与 mainline_tracker

**根因**: 两套主线追踪系统并存：
- `mainline_info` (from `build_mainline_info`): 只用 `_conc_state.signal`，信号经常为空
- `mainline_tracker` (from `MainlineTracker.update`): 用 `detect_all_signals`，能检测到信号

**数据验证**: 最近 346 天 review，`mainline_info.status` 全部为 `none`，但 `mainline_tracker` 经常有 CONFIRMED 主线。

**修复方案**: 以 `mainline_tracker` 为准，用 tracker 状态同步更新 `trade_plan.mainline_status`。

**修改文件**:
1. `quant/trade_plan.py`: `mainline_status` 从 `mainline_tracker` 读取（优先级高于 `mainline_info`）

**具体逻辑**:
```python
# 当前代码 (line 386-401):
_ml_status_from_info = _ml_info.get('status', 'none')
if _ml_status_from_info in ('confirmed', 'divergence', 'needs_repair'):
    plan['mainline_status'] = _ml_status_from_info
elif _ml_status_from_info == 'candidate':
    plan['mainline_status'] = 'candidate'
else:
    plan['mainline_status'] = 'none'

# 修复后:
# 优先从 mainline_tracker 读取
_tracker = prev_meta.get('mainline_tracker', {}) if prev_meta else {}
_tracker_statuses = [s.get('status', '') for s in _tracker.values()]
if 'CONFIRMED' in _tracker_statuses:
    plan['mainline_status'] = 'confirmed'
elif 'CANDIDATE' in _tracker_statuses:
    plan['mainline_status'] = 'candidate'
elif 'DEGRADED' in _tracker_statuses:
    plan['mainline_status'] = 'degraded'
else:
    # fallback 到 mainline_info
    _ml_status_from_info = _ml_info.get('status', 'none')
    plan['mainline_status'] = _ml_status_from_info if _ml_status_from_info != 'none' else 'none'
```

### 修复4: 注册 mainline_exit

**根因**: `UNIFIED_MAINLINE_EXIT = "mainline_exit"` 在 `action_router.py` 中使用，但没有对应的策略文件和注册。

**修复方案**: 创建 `quant/strategies/mainline_exit.py` 并注册。这个策略不需要选股（DEGRADED 意味着清仓），只需要返回空 picks。

**修改文件**:
1. 新建 `quant/strategies/mainline_exit.py`: 返回空 picks 的简单策略
2. `quant/strategies/__init__.py`: 注册 `mainline_exit`
