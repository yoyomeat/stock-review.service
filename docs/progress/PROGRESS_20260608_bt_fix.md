### 1.2 深度诊断发现

#### 发现1：55笔0%止损（sl=buy_price）

- 所有55笔 `sl_type=stop_entry_pct, sl_param=-5`，但 `stop_loss == buy_price`
- D+1 low 100%触发止损，D+1 low均值-4.75%，但D+1 close均值+1.62%
- **止损在最低点割肉，然后反弹**

根因：`quant/pipeline.py` 的 `_apply_regime()` 中：
```python
if action == "exit_all":
    exit_plan["stop_loss"] = round(ctx.close, 2)  # close == buy_price
```
`evaluate_regime()` 对冰点期/断崖下跌返回 `exit_all`，然后 `_apply_regime` 把止损设成收盘价（=买入价），0%止损。

#### 发现2：CANDIDATE_PROBE 仓位过低（均值4.5% vs V4的21%）

仓位链路：
```
CYCLE_BASE_POS=100 → _alloc(3)=[60,40]
  → × MAINLINE_POS_MULT['CANDIDATE']=0.3 → _ma=18
  → Pipeline pos_mult 衰减 → 最终 alloc=1~6%
```

V4做法：`BASE_POS=70 × 0.3 = 21%`，不经过Pipeline多层衰减。

#### 发现3：同股连续pick导致120次减仓

- 18只股票连续5天+被pick
- 每天alloc不同（72%→54%→36%→22%），触发"同股减仓"57笔
- V4不做同股减仓，持仓直到DEGRADED/到期

#### 发现4：止损触发率59.9%

| 止损原因 | 笔数 | 占比 |
|---------|------|------|
| regime exit_all → sl=buy（0%止损） | 55 | 18.1% |
| D+1 low 触发 SL-5% | 127 | 41.8% |
| 合计触发 | 182 | 59.9% |

V4 SL-5%触发：150/304 (49.3%)。

## 二、修复方案

遵循架构原则：单一修改点、禁止反向依赖、策略函数只做计算。

### Fix 1：`_apply_regime` exit_all 不覆盖止损

**文件**：`quant/pipeline.py` `_apply_regime()`
**改动**：删除 exit_all 分支中 `exit_plan["stop_loss"] = round(ctx.close, 2)` 两行
**原则**：exit_all 语义是"立即清仓"，不是"把止损收到买入价"。回测引擎已有 `regime_force_close()` 处理清仓。
**备份**：`pipeline.py.bak_20260608_regime_fix`

### Fix 2：CANDIDATE_PROBE 仓位提升

**文件**：`config/strategy_rules.py` `MAINLINE_POS_MULT`
**改动**：`CANDIDATE: 0.3 → 0.8`
**原则**：纯配置修改，零逻辑，单一修改点
**备份**：`strategy_rules.py.bak_20260608_cand_alloc`

### Fix 3：同股 carry 不减仓

**文件**：`quant/bt_order_executor.py` `execute_new_trades()`
**改动**：`elif alloc < cur_alloc` 分支改为 `pass`（不减仓）
**原则**：V4行为，持仓直到DEGRADED/到期才退出
**备份**：`bt_order_executor.py.bak_20260608_no_reduce`
