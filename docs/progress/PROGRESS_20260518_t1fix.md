# 2026-05-18 回测引擎 T+1 持仓 Bug 修复

日期: 2026-05-18
状态: 完成

---

## 一、问题发现

分析 2025 年 2 月回测持仓时发现：新炬网络(605398) 02/05~02/12 连续 8 天涨停(+10%)，
但回测显示持有期间有 -9.2% 和 -9.19% 的亏损。

## 二、根因分析

回测引擎的 T+1 执行机制存在 **显示与 P&L 计算 Bug**：

- D 日生成 picks → 用 D+1 开盘价作为 entry_price 创建持仓
- 但该持仓 **立即** 被加入 open_positions，并用 **D 日收盘价** 做 mark-to-market
- 当 D+1 开盘价 > D 日收盘价（如涨停后跳空高开），entry > mark → 虚假亏损

具体案例（02/07）：
- D 日(02/07) 收盘价: 37.15（涨停）
- D+1(02/10) 开盘价: 40.865（跳空高开）
- entry_price: 40.91（= 40.865 + 0.1% 滑点）
- mark: 37.15（= D 日收盘价）
- unreal: -9.2%（**虚假亏损**，实际 02/10 才执行买入）

## 三、修复方案

仅修改 `backtest_engine.py`，共 4 处改动：

### 改动 1：新建持仓记录创建日
```python
open_positions[code] = {
    ...
    "_open_day_idx": i,  # T+1 fix: track creation day
}
```

### 改动 2：Mark-to-market 排除当日新建持仓
```python
if p.get("_open_day_idx") == i:
    curr_unrealized_map[code] = 0.0
    continue
```

### 改动 3：stock_details 标记 pending 并归零浮盈
```python
"unreal_pct": 0 if p.get("_open_day_idx") == i else ...,
"pending": p.get("_open_day_idx") == i,
```

### 改动 4：day_end_exposure 排除待开仓
```python
day_end_exposure = round(sum(
    p["alloc"] for p in open_positions.values()
    if p.get("_open_day_idx") != i
), 1)
```

### 4.4 核心修正
- 待开仓持仓（pending=True）不再计入当日 P&L
- D+1 执行后才开始计算浮盈
- 净值曲线更准确反映实际交易时间线

## 五、注意事项

- 回测引擎有磁盘缓存（`/tmp/stock_review_bt_cache/`，TTL=1小时）
- 修改后需清缓存或等 TTL 过期才能看到新结果
- API 层也有内存缓存，需重启 uvicorn
